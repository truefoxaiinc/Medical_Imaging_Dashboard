# NVIDIA production staging — medical.truefoxaiinc.com

This is a **deployment runbook**, not a claim that the server has been changed. Research/demo only; **de-identified images only**. Do not use for diagnosis or clinical decisions.

## Isolation and preflight

Do not alter any existing Docker Compose project, Docker network, Apache vhost, Virtualmin configuration, UFW/nftables rules, or shared NVIDIA runtime settings without separate review.

On the Ubuntu host, first inspect:

```bash
nvidia-smi
docker version
docker compose version
docker info --format '{{json .Runtimes}}'
docker ps --format 'table {{.Names}}\t{{.Ports}}'
sudo ss -ltnp | grep -E ':(80|443|18501)\b' || true
sudo apache2ctl -S
```

**Stop** if the GPU is unavailable to Docker, if loopback port 18501 is occupied, or if existing resources are under memory pressure. Install/configure NVIDIA Container Toolkit only in a separately approved host maintenance window; it can affect Docker globally. Test first:

```bash
docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
```

The CUDA test image requires a compatible host NVIDIA driver. If the tag is unavailable, select a compatible supported tag. The test may download an image but should not modify running containers.

## Staging deployment

Use a dedicated unprivileged Linux deployment account with access to Docker (note that Docker group membership grants root-equivalent privileges). Use a dedicated directory such as `/srv/medical-imaging`; ensure the account can write there.

```bash
git clone --branch docker/streamlit-ollama-setup https://github.com/truefoxaiinc/Medical_Imaging_Dashboard.git /srv/medical-imaging
cd /srv/medical-imaging
cp .env.example .env
mkdir -p .streamlit
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
chmod 600 .streamlit/secrets.toml
${EDITOR:-nano} .streamlit/secrets.toml
docker compose -p medical-imaging -f compose.yaml -f compose.gpu.yaml config --quiet
docker compose -p medical-imaging -f compose.yaml -f compose.gpu.yaml build dashboard
docker compose -p medical-imaging -f compose.yaml -f compose.gpu.yaml up -d
docker compose -p medical-imaging -f compose.yaml -f compose.gpu.yaml exec ollama ollama pull llama3
docker compose -p medical-imaging -f compose.yaml -f compose.gpu.yaml ps
curl -fsS http://127.0.0.1:18501/_stcore/health
docker compose -p medical-imaging -f compose.yaml -f compose.gpu.yaml exec dashboard python -c 'import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else "NO GPU")'
docker compose -p medical-imaging -f compose.yaml -f compose.gpu.yaml exec ollama ollama ps
```

**Do not proceed** if the dashboard image lacks a CUDA-enabled PyTorch build. The base Dockerfile installs dependencies from requirements.txt and does **not** guarantee CUDA-enabled torch; verify with the command above and prepare a compatible pinned CUDA PyTorch image if needed. The dashboard and Ollama both request the GPU; the RTX 3060 may not have enough VRAM to run both models simultaneously. Verify actual free VRAM, reduce model size or use sequential workloads. Never assume inference is GPU-accelerated merely because Compose accepts `gpus: all`.

The `llama3` model is relatively large; prefer a smaller tested model if GPU memory is insufficient, but update the Streamlit default model to match before use.

## DNS and Apache / Virtualmin

1. Add an A record for `medical.truefoxaiinc.com` pointing to the intended public server IP in the domain's authoritative DNS provider.
2. Confirm DNS resolves correctly and obtain an HTTPS certificate through Virtualmin for the **new dedicated virtual server**. Do not edit existing vhosts.
3. After staging passes functional and security checks, configure **only this dedicated Apache vhost** to reverse proxy `/` to `http://127.0.0.1:18501/` and WebSocket traffic to the same upstream. Use Apache's supported WebSocket proxying with `mod_proxy`, `mod_proxy_http`, and (where required) `mod_proxy_wstunnel`.
4. Set `ProxyPreserveHost On`, forwarded HTTPS headers, and conservative upload/body limits. Disable public indexing and enforce an additional access gate (VPN, IP allowlist or external identity provider) beyond Streamlit's demo login.
5. Run `apache2ctl configtest` before any Apache reload. Verify other domains and services after reload.

Example **vhost directives only** (insert inside the newly created domain's SSL virtual host, not global Apache configuration):

```apache
ProxyPreserveHost On
ProxyPass / http://127.0.0.1:18501/ upgrade=websocket
ProxyPassReverse / http://127.0.0.1:18501/
RequestHeader set X-Forwarded-Proto "https"
```

The `upgrade=websocket` syntax requires a sufficiently recent Apache 2.4. Validate the installed Apache modules/version and Virtualmin's generated vhost before applying it. Avoid duplicate ProxyPass rules generated by Virtualmin. A simple HTTP 200 is not sufficient: test Streamlit session/WebSocket operation.

## Acceptance tests

- Docker health is healthy, NVIDIA available inside dashboard, and Ollama responds on the private network.
- Login fails with wrong credentials and succeeds with valid credentials.
- One **de-identified** sample chest X-ray completes BiomedCLIP, RAG, LLM, and review/download flow.
- Verify GPU utilization and memory use while processing, and confirm no unintended image/PHI logging.
- HTTPS certificate valid; domain's WebSocket connection stable; direct public access to port 18501 blocked by loopback binding.
- Existing Apache sites, Docker containers, and server health remain unchanged.

## Rollback

Before DNS/proxy cutover, stop only this project:

```bash
cd /srv/medical-imaging
docker compose -p medical-imaging -f compose.yaml -f compose.gpu.yaml down
```

Do **not** use `down -v`, global prune commands, or restart Docker. If proxying has been enabled, revert only the dedicated `medical.truefoxaiinc.com` vhost directives and validate Apache configuration before reload.

## Security blockers

The public repository contains `medical.pem`. Revoke/rotate the key if active and plan coordinated removal from repository history. The Streamlit login is a demo gate, not sufficient authentication/audit for identifiable clinical data. Clinical thresholds and reporting must undergo independent validation before any clinical use.
